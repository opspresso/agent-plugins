# 리뷰 렌즈

`general-correctness`는 항상 돌린다. 나머지는 신호가 있거나 사용자가 지정했을 때만 돌린다.

## general-correctness

모든 리뷰에서 실행한다. 무엇을 보나.

- 잘못된 제어 흐름과 놓친 경계 조건
- 깨진 API 계약
- 빠진 에러 처리
- null, 빈 입력, 순서, 동일성, 시간에 대한 잘못된 가정
- 코드가 스스로 밝힌 의도와 다르게 동작하는 곳

동작·유지보수·안전·테스트 신뢰도에 영향을 주는 것만 보고한다.

## runtime-safety

**신호** — 에러 처리, 재시도, 타임아웃, 취소, 동시성, 락, 비동기 코드. 인증·권한 검사·
토큰·시크릿·파일 경로·역직렬화 같은 보안 민감 경로. null 처리, 검사 없는 캐스팅, panic,
강제 언래핑, 자원 수명, 커넥션 관리.

**묻는 것**

- 현실적인 입력에서 런타임에 실패할 수 있나.
- 그 실패가 데이터를 흘리거나 권한 검사를 건너뛰거나 상태를 깨뜨리나.
- 모든 경로에서 정리(cleanup)가 일어나나.
- 재시도와 타임아웃에 상한이 있나.

## data-layer

**신호** — SQL, 마이그레이션, 스키마, 인덱스, 리포지터리, 쿼리 빌더, ORM, 검색 색인,
캐시 키. 저장 형태나 쿼리 의미를 바꾸는 코드.

**묻는 것**

- 이 쿼리가 의도한 행을 돌려주나.
- 인덱스·페이지네이션·정렬이 운영 데이터 규모에서 안전한가.
- N+1이나 상한 없는 스캔이 생기나.
- 마이그레이션이 하위 호환이고 무중단 배포에 안전한가.
- 캐시 키와 무효화 규칙이 맞나.

## architecture-boundary

**신호** — 모듈 경계, 의존 방향, 공개 인터페이스, 트랜잭션, 서비스 오케스트레이션,
이벤트 발행. 로직을 계층 사이로 옮기거나 새 공용 추상을 만드는 변경.

**묻는 것**

- 소유권 경계가 유지되나.
- 새 추상이 그 값을 할 만큼 깊은가. 얕은 래퍼 하나를 늘린 것은 아닌가.
- 트랜잭션 경계가 명시적이고 정확한가.
- 관계없는 모듈끼리 묶이지 않았나.
- 요구를 만족하는 더 국소적인 변경이 있지 않나.

## tests-conventions

**신호** — 테스트 없이 바뀐 운영 동작. 테스트 파일, 픽스처, 스냅샷, 목, 생성 파일,
라우트 핸들러, 공개 API. 저장소의 이름·디렉터리·프레임워크 관례.

**묻는 것**

- 바뀐 동작이 맞는 층위에서 덮이나.
- 목이 정작 검증해야 할 동작을 가리고 있지 않나.
- 스냅샷이나 생성 파일을 갱신해야 하나.
- 저장소의 테스트 이름과 위치 관례를 따르나.
- 상위 테스트가 덮고 있어서 없어도 되는 경우인가.

## 심각도

- **Critical** — 버그일 가능성이 높음, 데이터 손실, 보안 문제, 깨진 계약, 위험한
  마이그레이션. 머지를 막아야 하는 것.
- **Warning** — 가능성 있는 문제이거나 유지보수 위험. 고쳐야 하지만 머지를 분명히
  막을 정도는 아닌 것.
- **Suggestion** — 위험이 낮은 개선, 단순화, 가독성·테스트 보강.

추측성 지적은 쓰지 않는다. 정해진 범위 안에서 위험을 확인하지 못했으면 빼거나,
"남은 위험"에 질문으로 남긴다.
