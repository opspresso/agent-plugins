# 시각 AI 티 카탈로그

AI가 만든 화면·리포트·다이어그램에서 반복해 나타나는 시각 패턴과 처방을 모아 둔 참고
파일이다. `frontend-design`이 방향을 정하기 전에 펼쳐 보고, 같은 플러그인의 다른 디자인
스킬 본문에 있는 짧은 규칙은 이 파일을 압축한 것이다. 규칙이 서로 어긋나면 이 파일을
따른다.

강도 표시:

- **강** — 모델 계열과 무관하게 반복해 나타나는 신호. 발견하면 거의 항상 바꾼다.
- **중** — 정당한 쓰임이 있는 장치. 근거 없이 쓰거나 남발할 때만 바꾼다.

## 0. 먼저 지킬 것

- **사용자 지시가 이긴다.** 사용자가 이 목록에 있는 스타일을 그대로 요구하면 그대로
  만든다. 이 파일은 지시가 없을 때 쓰는 기본값이다.
- **프로젝트 디자인 시스템이 이 파일을 이긴다.** 토큰과 컴포넌트가 이미 있으면 그것을 쓴다.
- **컴포넌트 자체가 문제인 적은 없다.** 카드·pill·둥근 모서리·큰 숫자는 실제 구조를
  표현하면 정당하다. 구조 없이 "디자인된 것처럼" 보이려고 쓸 때만 티가 된다.
- **빼는 것으로 끝내지 않는다.** 클리셰를 걷어낸 자리에는 주제에서 길어 올린 대안을
  넣는다. 아무것도 없는 화면은 클리셰보다 나쁘다.

## 1. 팔레트 — 강

| 패턴 | 처방 |
|---|---|
| 흰 지면 위에 뜬 보라→파랑 그라데이션 히어로 | 그라데이션을 지우고 단색 지면에 활자로 위계를 만든다. 유지하려면 주제에 근거를 댄다 |
| 크림색 지면(#F4F1EA 부근) + 세리프 디스플레이 + 테라코타 액센트 | 셋이 함께 오면 기성품이다. 둘 이상을 주제에서 다시 고른다 |
| 니어블랙 지면에 애시드 그린·버밀리언 한 방 | 어두운 지면을 유지하려면 액센트를 주제 쪽으로 옮긴다 |
| 중립색이 정확한 무채색(#808080, #F5F5F5) | 액센트 쪽으로 채도를 조금 섞는다. 고른 중립과 남은 중립은 눈에 보이게 다르다 |
| 액센트색이 상태(성공·경고·위험)를 겸함 | 상태색은 액센트와 별개 레인에 둔다. 액센트를 위험색으로 재활용하지 않는다 |
| 색이 넷을 넘고 각자 역할이 없음 | 4~6개로 줄이고 색마다 이름과 역할을 붙인다 — 지면, 본문 먹, 액센트, 괘선, 상태 |

```css
/* 남은 중립 */  --muted: #808080;
/* 고른 중립 */  --muted: #7B7F87;  /* 액센트 #2A5CD6 쪽으로 미세하게 틀었다 */
```

## 2. 활자 — 강

| 패턴 | 처방 |
|---|---|
| Inter·Space Grotesk·Poppins를 이유 없이 기본값으로 | 시스템 스택으로 가거나, 주제에 맞는 face를 고르고 왜 골랐는지 한 줄로 밝힌다 |
| 디스플레이와 본문이 같은 패밀리·같은 굵기 | 두 역할이 대화하게 만든다. 한 패밀리로 갈 거면 굵기·크기·자간 대비를 확실히 벌린다 |
| 본문 한 줄이 100자를 넘음 | 라틴 65자, 한국어 40~45자 안팎으로 measure를 묶는다 |
| 제목이 어색한 자리에서 줄바꿈됨 | 제목에 `text-wrap: balance`를 건다 |
| 대문자 라벨에 자간이 없음 | `letter-spacing: 0.06em` 정도를 준다 |
| 화면 전체가 중앙정렬 | 중앙정렬은 짧은 표제에만 쓴다. 본문·목록·표는 왼쪽 정렬로 되돌린다 |
| 스케일 없이 필요할 때마다 크기를 지정 | 타입 단계를 먼저 정하고 그 안에서만 고른다 |

## 3. 레이아웃과 컴포넌트 — 강

| 패턴 | 처방 |
|---|---|
| 모든 요소에 같은 radius(12~16px) | radius를 위계에 쓴다. 큰 면과 조작 대상은 다른 값을 갖는다 |
| 액센트 바나 좌측 레일이 달린 둥근 카드의 반복 | 카드를 걷고 여백과 괘선으로 나눈다. 카드는 항목이 독립적으로 조작·이동될 때만 쓴다 |
| 내용이 셋이어서가 아니라 셋이 보기 좋아서 만든 3열 그리드 | 항목 수를 내용이 정하게 한다. 둘이면 둘, 다섯이면 다섯으로 둔다 |
| 같은 요소에 border와 shadow를 함께 | 하나만 고른다. 종이에 가까운 문서는 border, 떠 있는 조작 대상은 shadow |
| 절마다 다른 배경색 밴드 | 여백과 얇은 선으로 나눈다 |
| 메모·계획 문서에도 화면을 채운 히어로 | 레지스터를 낮춘다. 실무 문서 대부분은 제목 블록이면 충분하다 |
| 데이터가 적은데 빈 자리를 카드로 채움 | 비워 둔다. 여백은 미완성이 아니다 |

## 4. 장식 기표 — 중

| 패턴 | 처방 |
|---|---|
| 이모지로 절을 구분하거나 불릿을 대신함 | 지운다. 구분은 활자 크기와 여백이 한다 |
| `01 / 02 / 03` 번호 마커 | 순서가 실제 정보일 때만 정직하다. 절차나 일정이 아니면 지운다 |
| 헤어라인 괘선과 좁은 단으로 만든 신문 조판 흉내 | 주제가 실제로 편집 지면일 때만 쓴다 |
| 근거 없는 대형 수치("99.9%", "10x") | 출처를 못 대는 숫자는 싣지 않는다 |
| 글래스모피즘·네온 글로우·`backdrop-filter` 남발 | 한 곳으로 제한하거나 전부 뺀다 |
| 의미 없는 아이콘이 모든 항목 앞에 | 스캔을 돕는 자리에만 남긴다 |

## 5. 모션 — 중

| 패턴 | 처방 |
|---|---|
| 스크롤 진입 페이드업이 모든 요소에 | 한 번만 쓰거나 아예 뺀다 |
| 카운트업 숫자 | 쓰지 않는다. 올라가는 동안 독자는 그 값을 읽지 못한다 |
| 자동재생 캐러셀·시차 스크롤 | 쓰지 않는다. 사용자가 속도를 통제하지 못한다 |
| 장식 전용 hover 변형 | 조작 가능함을 알리는 변화만 남긴다 |
| `prefers-reduced-motion` 미대응 | 전부 끄되 상태 변화의 피드백은 즉시 반영되게 남긴다 |

모션은 예산이다. 여러 곳에 흩뿌린 효과보다 한 곳의 정돈된 움직임이 낫다. 지나친
애니메이션 자체가 AI 티다.

## 6. 콘텐츠와 문구 — 강

| 패턴 | 처방 |
|---|---|
| lorem ipsum, "Your headline here" | 첫 초안부터 실제 내용을 넣는다. 실제 길이의 제목과 긴 값으로 레이아웃을 검증한다 |
| 눌러도 아무 일이 없는 버튼 | 지우거나, 실제 시스템이 이어받는 경계를 화면에 밝힌다 |
| 백엔드 용어가 그대로 UI 라벨로 | 사용자가 부르는 이름으로 바꾼다. `webhook config` → `알림` |
| 버튼 이름이 결과를 말하지 않음("확인", "제출") | 결과를 쓴다. `발행` 을 누르면 `발행됨` 이 뜬다 |
| 사과하는 오류 메시지, 원인도 처방도 없는 오류 | 무엇이 실패했고 무엇을 하면 되는지 쓴다 |
| 같은 행동을 자리마다 다른 이름으로 부름 | 화면 하나 안에서 어휘를 통일한다 |

## 7. 마지막 관문 — 주제 치환 검사

내보내기 전에 한 번 묻는다. **주제를 이웃 주제로 바꿔도 이 시각 컨셉이 똑같이 말이
되는가?** 그렇다면 방향이 너무 일반적이다. 구성·활자·색·이미지·상호작용 중 하나를
주제의 재료에서 다시 길어 올린다.

색만 바꾼 같은 히어로와 같은 카드 그리드는 여전히 같은 디자인이다. 바꿀 거면 구성,
밀도, 형태 언어, 내비게이션 중에서 바꾼다.
