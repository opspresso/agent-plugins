# 의미 패턴

다이어그램 유형은 배치를 정하고, 의미 패턴은 어떤 상태와 연결을 반드시 보여야 하는지
정한다. 아래 패턴이 요청의 핵심일 때만 선택한 유형 위에 하나를 적용한다.

## 병목과 대기열

**신호:** 여러 입력이 한 처리기로 모임, 처리 용량 제한, backlog, retry.

- 입력, queue, worker, 결과를 서로 다른 요소로 둔다.
- `arrival rate`, `capacity`, `queue depth` 중 주어진 값을 가까이에 적는다.
- retry가 원래 입력과 합쳐지는 지점을 명확히 그린다.
- queue를 단순 화살표 굵기로 대신하지 않는다. 대기 상태가 의미이므로 node로 보인다.

## 신뢰 경계와 허용 경로

**신호:** public/private zone, ingress, authorization, permitted/blocked path.

- 경계는 영역으로 먼저 그리고 연결선을 나중에 배치한다.
- 경계 통과에는 입력에 주어진 protocol이나 정책을 적는다. 둘 다 없으면 `허용된 진입`처럼
  관계의 성격만 적고 구체적인 protocol·정책 이름을 추측하지 않는다.
- 허용과 차단을 색만으로 구분하지 말고 line style과 text를 함께 쓴다.
- 우회 경로가 없다는 사실을 보여야 하면 차단 지점도 생략하지 않는다.

## 역할 간 handoff

**신호:** 승인, 검토, escalation, 부서 간 인계.

- actor마다 lane을 주고 handoff를 lane 경계에서 보이게 한다.
- 기다림과 실제 작업을 구분한다.
- 승인 후 되돌아가는 경로가 있으면 종료처럼 그리지 않는다.
- 시스템 자동화와 사람 판단을 같은 node 모양으로 쓰지 않는다.

## feedback loop

**신호:** 결과가 다음 주기의 입력을 바꿈, 학습, 측정 후 조정.

- 시작점 없는 원형 장식이 되지 않도록 trigger와 관찰 결과를 적는다.
- 각 단계가 무엇을 읽고 무엇을 바꾸는지 동사로 쓴다.
- 되먹임선은 진행선과 다른 style을 사용한다.
- 한 번만 실행되는 순서는 loop로 과장하지 않는다.

## 정책 평가

**신호:** 여러 rule, allow/deny, 첫 실패, 조건부 skip.

- rule의 평가 순서를 유지한다.
- `pass`, `fail`, `skipped`, `not reached`를 구분한다.
- 결과가 달라지는 첫 지점을 강조한다.
- 모든 rule을 통과한 경로와 조기 종료 경로를 모두 닫힌 상태로 끝낸다.

## lifecycle

**신호:** 생성, 활성, 일시중지, 종료, 복구.

- 정상 경로와 예외 경로를 line style로 구분한다.
- terminal state와 일시 상태를 shape나 label로 구분한다.
- 어떤 event가 transition을 일으키는지 선에 적는다.
- 불가능한 전이를 보기 좋다는 이유로 연결하지 않는다.

## 장애 전파와 방어

**신호:** 한 실패가 다음 계층에 미치는 영향, timeout, circuit breaker, fallback.

- 실패 원점, 전파 경로, 방어 지점, 남은 영향 범위를 분리한다.
- 방어 장치는 실제로 막는 failure mode와 연결한다.
- fallback을 정상 흐름과 같은 굵기로 그리지 않는다.
- 관측 가능성 도구는 방어가 아니라 탐지이므로 별도 의미로 표시한다.

## 조합 제한

한 장에 패턴을 두 개 이상 겹치면 읽기 규칙이 충돌하기 쉽다. 둘 다 중요하면 overview에는
경계와 핵심 경로만 남기고, 정책 평가나 장애 전파는 별도 detail로 분리한다.
