# 한국어 AI 티 카탈로그

AI가 쓴 한국어에서 반복해 나타나는 말투·어법·서식 패턴과 처방을 모아 둔 참고 파일이다.
`korean-humanize` 스킬이 윤문할 때 펼쳐 보고 다른 작성 스킬 본문의 짧은 규칙은 이 파일을
압축한 것이다. 규칙이 서로 어긋나면 이 파일을 따른다.

강도 표시:

- **강** — 사람 글과 대조해 실측으로 확인된 신호. 발견하면 거의 항상 고친다.
- **중** — 유형론 근거는 분명하지만 사람도 가끔 쓴다. 남발(문서 안 반복)일 때 고친다.

## 0. 먼저 지킬 것

- **빼기 전용이다.** 처방은 티를 빼는 방향으로만 쓴다. 원문에 없던 비유·수사·감탄·상투구를
  새로 심지 않는다. 리듬을 만들려고 내용을 지어내지 않는다.
- **사실은 글자 단위로 보존한다.** 수치·날짜·단위·고유명사·제품명·큰따옴표 안 인용·법조문·
  코드·명령어·URL 은 건드리지 않는다.
- **격식은 원문을 따른다.** 합니다체는 합니다체로, 해라체는 해라체로. `했다` 를 `하였다` 로
  올리지 않고 `~인데요` `~거든요` 같은 살아 있는 구어 종결은 남긴다.
- **표준 기술 용어는 원어로 둔다.** API·토큰·파이프라인·prompt·배포·롤백처럼 업계가 그대로
  쓰는 말을 우리말로 억지 번역하지 않는다. 광고성 buzzword(seamless·robust·leverage)만 푼다.
- **개조식 문서의 불릿·번호는 정상이다.** 회의록·기안문·PR 본문·체크리스트의 목록을 산문으로
  풀지 않는다. 산문(보고서 본문·칼럼·블로그)에서 불릿이 문단을 대신할 때만 손댄다.
- **표의 어휘는 예시다.** 같은 성격의 표현(만능 추상어·hedging·번역투·상투구)은 같은 처방을
  따른다. 단, "구체 동사·수치로" 처방은 원문에 그 근거가 있을 때만 실행한다. 근거가 없으면
  그대로 두고 윤문 메모에 "근거 없어 보존"이라고 적는다. 지어내서 채우지 않는다.

## 1. 대구·변환 공식 — 강

실측에서 가장 강한 신호다. `A가 아니라 B` 부정 대구는 AI 글이 사람 글의 9배(개인 블로그
대비 18배)로 나온다. 세 모델(Claude·GPT·Haiku)에서 똑같이 나타나 모델 계열과 무관하다.

| 패턴 | 처방 |
|---|---|
| `단순히 A가 아니라 B다`, `A라기보다 B다`, `A를 넘어 B로` 부정 대구 | 발견하면 고친다. 1회여도, 첫 문장이어도 B 를 직접 단언한다. A 가 사실로 필요하면 뒤 문장으로 뺀다 |
| `X에서 Y로`, `X의 시대에서 Y의 시대로` 변환 슬로건 | 문서당 1회 이하. 나머지는 실제 변화를 동사로 서술한다 |
| `A인가, B인가` 질문형 대구 3회 이상 | 한 번만 남기고 평서문으로 |
| `먼저 … 반면 … 결국 …` 3단 문단 공식 | 접속사를 빼고 본문이 흐름을 잡게 한다 |

> 전: 이번 장애는 단순히 커넥션 풀 문제가 아니라 배포 절차의 문제였습니다.
> 후: 이번 장애는 배포 절차의 문제였습니다. 커넥션 풀은 그중 하나입니다.

원문에 없던 인과("그 결과로")나 수치를 보태지 않는다. A 를 살릴 때는 원문이 말한 관계만 옮긴다.

## 2. 쉼표 — 강

연결어미 뒤 쉼표는 단일 지표로 가장 잘 갈리는 신호다(사람 4% vs AI 20%, KatFish 2025).
한국어는 연결어미 자체가 호흡을 만들어서 쉼표가 필요 없다. 영어의 comma-after-conjunction
감각이 옮겨 온 것이다.

| 패턴 | 처방 |
|---|---|
| `-고,` `-며,` `-지만,` `-면서,` `-아서/-어서,` `-는데,` 뒤 쉼표 | 쉼표를 뺀다. 호흡이 길면 마침표로 끊는다 |
| 전체 문장의 절반 이상에 쉼표가 있음 | 일부를 마침표로 나누거나 연결어미로 흡수한다 |
| 쉼표가 셋 이상인 문장 | 두 문장으로 나눈다 |

> 전: 배포는 끝났지만, 캐시가 남아 있어서, 일부 사용자에게는 이전 화면이 보였습니다.
> 후: 배포는 끝났지만 캐시가 남아 있었습니다. 그래서 일부 사용자에게는 이전 화면이 보였습니다.

## 3. 리듬 — 강

AI 글은 문장 길이가 고르고 100자 넘는 문장이 거의 없다(사람 글의 1/10). 종결어미도
`~한다`·`~합니다` 한 가지로 이어진다.

| 패턴 | 처방 |
|---|---|
| 같은 종결 패턴(`~한다` / `~했다` / `~이다` / `~ㄹ 것이다` 등 시제·서법 단위) 4문장 이상 연속 | 다른 패턴이나 명사형 종결로 변주. 격식 자체는 바꾸지 않는다 |
| 문장 길이가 모두 30~50자 | 인접한 두 문장을 연결어미로 이어 긴 문장 하나를 만들고 짧은 문장 하나를 둔다. 쉼표를 보태지 않고 내용도 추가하지 않는다 |
| 문단마다 3~4문장 공식, 첫 문장이 늘 요약 | 일부 문단은 사례·수치·질문으로 시작한다 |
| `~고 있다` 진행형 남발 | 단순 시제로 환원 가능하면 환원("증가하고 있다" → "늘었다") |

메신저 3~5줄, 개조식 문서는 이 항목을 적용하지 않는다.

## 4. 결산·도입 상투구 — 강

사람은 거의 안 쓰고 AI는 자동으로 붙이는 라벨이다. 사람 판독 정확도를 60%에서 90%로 올린
핵심 지표이기도 하다.

| 패턴 | 처방 |
|---|---|
| `결론적으로` `요약하면` `정리하자면` `종합하면` `이를 통해` `그러므로` | 뺀다. 마지막 문단 자체가 결론이다. 합산 3회 이상이면 확실한 신호 |
| `다음과 같은` `다음과 같이 요약할 수 있다` `크게 세 가지로 나눌 수 있다` | 도입구를 빼고 바로 본론 |
| `~라고 할 수 있다` `~라고 볼 수 있다` | 단언 가능하면 `~다`, 관측이면 `~로 보인다` 하나만 |
| `매우 중요하다` `주목할 만하다` `시사하는 바가 크다` `간과할 수 없다` | 빼거나 구체 근거로("X 없이는 Y 가 안 된다") |
| `~할 때입니다` `~시점입니다` `~의 새로운 장을 열다` `~시대가 도래했다` 결말 공식 | 구체 동사 단언으로, 문서당 1회 이하 |
| 헤딩 아래 `이 절에서는 ~를 다룬다` 안내문 | 뺀다. 본문이 바로 시작해야 한국어 글답다 |

> 전: 결론적으로, 캐시 계층 도입은 매우 중요하다고 할 수 있습니다.
> 후: 캐시 계층이 없으면 p99 가 목표치 200ms 를 넘습니다.

## 5. 과장·정도부사·만능 추상어 — 중

| 패턴 | 처방 |
|---|---|
| `혁신적` `획기적` `압도적` `폭발적` `파격적` `전례 없는` `강력한` `대대적인` | 수치·사실로 바꾸거나 뺀다 |
| `매우` `정말` `상당히` `대단히` `크게` | 대부분 뺀다. 강조가 필요하면 비교 수치 |
| `개선` `강화` `활용` `효율화` `최적화` `고도화` `안정화` `대응` `진행` `처리` | 무엇을 어떻게 하는지 동사와 대상으로("성능 개선" → "응답 시간을 1.2초에서 0.4초로") |
| `효과적인` `원활한` `적절한` `다양한` `유연한` `전략적 접근` `종합적인 검토` | 어떤 것인지 구체화하거나 뺀다 |
| `중요하고 핵심적인` 동의어 이중 수식 | 하나만 |
| `-성/-화/-적` 명사화 체인("전략적 방향성의 명확화") | 동사·형용사로 푼다("전략 방향을 분명히 한다") |
| 의인화 추상 주어("기술이 묻는다", "데이터가 말해 준다") | 사람·기관 주어로 바꾸거나 동사를 약화한다 |

> 전: 커넥션 풀 조정 등 다양한 최적화를 통해 시스템의 전반적인 안정성을 크게 강화했습니다. 5xx 는 0.8%에서 0.1%로 줄었습니다.
> 후: 커넥션 풀을 조정해 5xx 를 0.8%에서 0.1%로 줄였습니다.

수치가 원문에 있어서 가능한 처방이다. 원문이 "안정성을 크게 강화했습니다"뿐이면 "크게"만 빼고
둔다. 어떻게 강화했는지를 지어내지 않는다.

## 6. hedging — 중

| 패턴 | 처방 |
|---|---|
| `~할 수 있습니다` 가 문단에 3회 이상, 또는 확인된 사실에 붙음 | 사실이면 단언("줄일 수 있습니다" → "줄입니다"). 진짜 가능성인 것 하나는 남기고, 남길 때는 조건을 붙인다 |
| `~것으로 보입니다` `~것으로 판단됩니다` `~라고 여겨집니다` 가 모든 문장 끝에 | 확인한 것은 단언. 정말 모르는 것만 남긴다 |
| `~할 가능성이 있을 수 있다` `~로 보여질 수 있다` 이중·삼중 완곡 | 완곡 하나만 |
| `신중하게` `균형 잡힌` `양쪽 모두` `장점도 있지만` 균형 어휘 4회 이상 | 한쪽 단언, 구체 비교, 조건부("X 일 때는 A, Y 일 때는 B")로 |
| `~해야 한다` `~할 필요가 있다` 권고형 결말 5회 이상 | 주체를 밝힌 동사 단언, 조건문으로 변주 |
| 모르는 것을 `~로 보입니다` 로 얼버무림 | "확인 못 함", "오늘 중 확인해서 알림" 처럼 상태와 기한을 적는다 |

사내 메시지의 요청·거절에 쓰는 완충(`혹시`, `~할 것 같습니다`)은 hedging 남발이 아니다.
한 겹만 쓰면 제 역할이다. 보고·공지·사실 전달에서 완충을 쓰는 것이 문제다.

## 7. 번역투 — 중

| 패턴 | 처방 |
|---|---|
| `X에 대해(서) 논의한다` | `X를 논의한다` |
| `X에 있어(서)` | `X에서`, `X를 볼 때` |
| `X와 관련하여` `X와 관련된` | `X에`, `X의`, `X를 두고` |
| `X를 바탕으로` `X에 기반하여` 남발 | `X로`, `X를 보고`, `X를 근거로` |
| `X를 통해` 문단 3회 이상 | 일부만 `X로`, `X해서`. 1~2회는 사람도 쓴다 |
| `~에 의해 ~되었다` | 행위자를 주어로("경찰에 의해 진압되었다" → "경찰이 진압했다") |
| `~되어진다` `~지게 된다` 이중 피동 | `~된다` |
| `가지고 있다` `회의를 가지다` | `있다`, `회의를 하다`("경쟁력을 가지고 있다" → "경쟁력이 있다") |
| `합의가 이루어졌다` `개선이 이루어졌다` | `합의했다`, `개선했다` |
| 무생물 주어 + 만능 동사("이 기능은 사용자에게 편의를 제공한다") | 사람 주어나 부사절("이 기능으로 사용자는 두 번 클릭할 것을 한 번에 한다") |
| `그/그녀/그것/그들` 단락 3회 이상 | 생략하거나 호칭·명사구로. 영어 원문이 없는 글에서는 발동하지 않는다 |
| 명사 앞 3어절 이상 관형절 | 문장을 나누거나 뒤에 붙인다 |
| `-에서의` `-으로의` `-에의` 이중 조사 | 절·구로 푼다. 단순 `~의` 는 대상이 아니다 |
| 조사 없는 명사 나열("결제 실패 건수 증가 확인") | 동사로 푼다("결제 실패가 늘었다") |

## 8. 문두 접속사·메타 문장 — 중

| 패턴 | 처방 |
|---|---|
| `또한` `따라서` `즉` `나아가` `아울러` `게다가` `더욱이` 문두 5회 이상 | 대부분 뺀다. 필요하면 `그래서` `여기에` 로 변주 |
| 같은 문장·인접 문장 안 접속사 중복("또한, … 개선 또한") | 하나만 남기거나 `~도` 로 |
| `이는 ~` `이 점에서` `이러한` `이를` `이처럼` 지시 반복 | 본문에 녹이거나 뺀다 |
| `하지만` `그러나` 번갈아 남발 | 하나를 `그런데` 로 바꾸거나 뺀다 |
| `첫째, 둘째, 셋째` 가 문단 전체를 지배 | 기본은 보존. 4개 이상이 메트로놈처럼 이어질 때만 1~2개를 서술문으로 |
| `1) 2) 3)` 숫자 괄호 나열 | 본문에 녹이거나 `우선` `다음으로` 로 변주. 문서당 1회 이하 |

## 9. 서식 — 강

| 패턴 | 처방 |
|---|---|
| 이모지(✅ 🚀 💡 ⚠️)가 리스트 머리·헤딩·강조에 | 보고서·메일·문서에서는 전량 삭제. SNS·제품 카피만 예외 |
| 문장마다 핵심어 **볼드** | 본문 볼드는 거의 제거. 제목·라벨급에만 |
| 헤딩 `X: Y` 콜론 부제 공식("서론: 제조업의 미래") | 단일 명사구나 결론 문장으로. 학술·보고서의 실제 절 번호는 보존 |
| `## 도입 ## 본론 ## 결론` 도식 헤딩 | 산문이면 헤딩을 빼고 리포트면 헤딩에 결론을 담는다 |
| 대시(—) 부가 설명이 문장마다 | 문서당 1~2회. 나머지는 쉼표·괄호·문장 분리 |
| 따옴표 강조 5회 이상 | 인용에만 |
| 산문에서 3개 이상 연속 불릿 블록 | 문단으로 통합. 나열이 뜻을 갖는 자리만 남긴다 |
| 헤딩 아래 내용 없이 또 헤딩 | 빈 헤딩을 없앤다 |
| 표를 산문 대신 남용 | 비교·수치가 아니면 문장으로 |

## 10. 챗봇 잔재 — 강

대화창에서는 자연스러워도 사람에게 건네는 문서·메시지에서는 바로 티가 난다.

| 패턴 | 처방 |
|---|---|
| `물론입니다` `네, 알겠습니다` `좋은 질문입니다` | 뺀다 |
| `다음은 ~입니다` `~를 소개해 드리겠습니다` `~에 대해 알아보겠습니다` | 뺀다. 바로 본문 |
| `함께 살펴봅시다` `~해 보세요!` 독자에게 말 걸기 | 문서에서는 뺀다 |
| `도움이 되셨기를 바랍니다` `궁금한 점이 있으면 언제든지 말씀해 주세요` `좋은 하루 되세요!` | 뺀다. 메일 마무리는 `감사합니다` 한 줄 |
| `AI로서` `제가 작성한` `제 지식 범위에서는` 자기 언급·컷오프 면책 | 뺀다 |
| 느낌표 남발, `~하시면 됩니다` `~해 주시면 감사하겠습니다` 반복 | 마침표로, 요청 어미는 한 번만 |
| 한글 뒤 영어 병기를 매번 반복("~(Sovereign AI)") | 첫 등장만 병기 |
| `seamless` `robust` `leverage` `holistic` 광고성 영어 | 우리말로 푼다. 표준 기술 용어는 그대로 |

## 손대면 안 되는 것

| 대상 | 이유 |
|---|---|
| 수치·날짜·단위·고유명사·제품명·모델명 | 사실이 바뀐다 |
| 큰따옴표 안 직접 인용, 법조문, 코드·명령어·URL·경로 | 인용·실행 대상이다 |
| API·토큰·prompt·파이프라인·배포·롤백 등 표준 기술 용어 | 원어가 표준이다 |
| 원문의 격식(합니다체·해요체·해라체)과 장르 | 윤문은 장르를 바꾸는 일이 아니다 |
| 개조식 문서의 목록·번호·표 | 문서 구조다 |
| `~를 통해` `~것이다` `첫째/둘째` 의 1~2회 사용 | 사람이 더 자주 쓴다. 남발만 손댄다 |
| 원문에 이미 있는 대시·감탄·반문·구어 종결 | 사람 글의 증거다 |

## 자가 점검

윤문이 끝나면 아래를 훑는다.

과하게 고쳤는지 — 어기면 그 수정을 되돌린다:

1. 수치·고유명사·인용이 원문과 글자 단위로 같은가
2. 격식과 장르가 그대로인가
3. 변경률이 30%를 넘지 않는가. 변경률은 바뀌거나 지워진 글자 수를 원문 글자 수로 나눈 값이다.
   이모지와 10절 챗봇 문구를 지운 글자는 세지 않는다
4. 원문에 없던 수사·상투구·인과·수치를 새로 넣지 않았는가

덜 고쳤는지 — 어기면 더 고친다:

5. 1절 부정 대구, 2절 연결어미 뒤 쉼표, 4절 결산 상투구, 9절 이모지·볼드, 10절 챗봇 문구가
   남아 있지 않은가
