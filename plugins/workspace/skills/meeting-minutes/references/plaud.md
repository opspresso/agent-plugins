# Plaud 녹음에서 회의록 작성

Plaud 녹음을 요청했고 해당 MCP가 연결된 경우에만 읽는다. 일반 전사문 작성에 이 연결은 필요 없다.

## 입력과 전사 경로

- 전사문이 제공됐으면 그 자료로 작성한다. 필요 없는 계정 조회나 재전사를 하지 않는다.
- PLAUD 녹음이 대상이면 연결된 도구의 실제 schema를 확인한다. 공식 역할은
  `list_files`로 후보 찾기, `get_file`로 녹음 정보와 오디오 URL 조회다.
- 제목·날짜·녹음 시각·길이로 대상을 좁힌다. 같은 이름의 후보가 여럿이고 구별할 근거가
  없으면 목록을 보여 주고 대상을 확인한다. 상대 날짜는 사용자의 시간대를 기준으로 해석한다.
- 목록의 `duration`은 밀리초다. 날짜 필터의 시간대가 확인되지 않았으면 반환 시각을
  대조한다. 필터가 있는 목록의 page가 실제로 적용된다고 가정하지 않는다.

호스트 앱에서 Agent Knowledge 전사를 요청한 경우 다음 순서로 진행한다. 다른 환경에서는 실제
다운로드·전사 계약을 사용하며 호스트 앱의 파일 ID를 전제하지 않는다.

1. 선택한 녹음의 실제 ID·제목·시각·길이를 확인한다. `get_file`의 `source_ref`나 원본 URL은
   Agent Knowledge에 전달할 수 없다. 원본 URL을 모델 문맥이나 답변에 복사하지 않는다.
2. 사용자가 같은 녹음 파일을 Chat에 첨부하면 연결된 `audio-processing` 스킬을 읽고 그 파일 ID로
   `recording_import` → `audio_job_submit`을 진행한다. 첨부 한도를 넘는 녹음은 Agent Knowledge 콘솔에서 올리도록 안내한다.
3. 비동기 작업은 실제 작업 ID로 상태를 확인한다. 완료 전 결과를 전사문으로 사용하지 않으며
   오류·부분 처리·누락 구간을 확인한다. 성공한 작업을 다시 제출하지 않는다.
4. 원본 녹음 ID·시각·전체 길이와 전사 범위를 대조한 뒤 회의록을 작성한다.

`get_file`에 포함된 기존 전사·요약이나 `get_transcript`·`get_note` 결과를 Agent Knowledge 전사의
출력이라고 보고하지 않는다. Agent Knowledge 전사가 불가능하면 필요한 연결이나 파일 제공 방법을 알린다.
지정 전사 요청을 수행할 수 없어 기존 PLAUD 전사문으로 대체하려면 사용자의 허가가 필요하다.
처음부터 기존 전사문으로 회의록을 요청했다면 그 권한으로 진행하고 전사 출처를 명시한다.

인증·접근 오류는 OAuth 연결을 확인한다. URL·서명 query·token을 회의록,
Notion 본문이나 장기 기억에 남기지 않는다. 녹음 ID를 Studio 파일 ID로 대신 쓰지 않는다.
현재 호스트 앱의 `FetchUrl`·문서용 `File`에는 오디오 다운로드·전사 기능이 없다.
